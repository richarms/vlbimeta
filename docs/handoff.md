# Recorder handoff contract, version 1

This contract is maintained identically in `katsdpvlbi/docs/handoff.md` and
`vlbimeta/docs/handoff.md`. Changes require compatible releases of both packages.
The optional cross-repository test in `vlbimeta` checks both the documents and
an actual proxy-to-postprocessor handoff with simulated jive5ab responses.

## Paths

`data_dir` is the shared data-volume root, normally `/var/kat/data` in both
containers. Neither caller appends the capture ID to this argument. `cbid` is
the capture-block ID; `stream` is the SDP output stream name, such as `sdp_vdif`.
`cbid` contains decimal digits only, as generated by SDP. `stream` is a
case-sensitive identifier matching `[A-Za-z0-9][A-Za-z0-9_.-]*`, with `..`
forbidden. This makes the underscore between capture ID and stream unambiguous.
Whitespace is rejected rather than stripped.

```text
<data_dir>/
  .vlbi/<cbid>/<stream>/
    raw.writing/                  # recorder-owned, not consumable
    raw/                          # recorder-closed, retained input
      capture.json
      <cbid>_<stream>.00000000     # decimal shard suffix; width is not fixed
      ...
  <cbid>_<stream>.vdif.writing/    # vlbimeta-owned unpublished VDIF
  <cbid>_<stream>.vdif/            # published VDIF and DLM metadata.json
  <cbid>_<stream>.metadata.writing/
  <cbid>_<stream>.metadata/        # companion products and provenance
    metadata.json
    capture.json                  # copy of the input inventory
    scan_manifest.json            # currently generated in antab mode
    <experiment><station>.antab    # antab mode
    tsys/
    catalogue/
```

The `.writing` and final names represent successive states, not two copies to
create together. The product-type suffixes `.vdif` and `.metadata` distinguish
products even when stream names themselves contain `metadata` or `vdif`.
Raw capture staging has no ingest `metadata.json`; it is not a published product.
No automatic search of older flat or capture-nested `_vdif`/`_antab` paths occurs.

## Recorder ownership

The controller supplies `VLBI_STREAM_NAME=<stream>` and `DISK_PATHS=<data_dir>`.
The stream environment variable is required for `capture-init`; there is no
implicit `sdp_vdif` default. The KATCP requests remain `capture-init <cbid>` and
`capture-done`. The controller-managed path uses the first data disk, as before.
The manual `record-start`/`net2file` debugging paths do not provide this handoff.

On capture-init the recorder exclusively creates `raw.writing`, refuses an
existing raw or unfinished capture for the same identity, and sets the jive5ab
scan name to `<cbid>_<stream>`. jive5ab may temporarily nest that scan directory
inside `raw.writing`; only the recorder flattens it after stopping.

On capture-done the recorder requires a successful stop response, or the explicit
already-stopped response (code 6, `Not doing record`). For code 1, as observed
with the pinned jive5ab build, it polls `record?` for up to ten seconds and
requires an explicit `off` response before proceeding. Code 1 by itself never
qualifies as evidence that it is safe to publish the handoff. A failed query,
unexpected state, or timeout leaves the capture unfinished.
The recorder then validates a non-empty set of non-empty, regular shard files,
writes `capture.json`, and renames `raw.writing` to `raw` on the same filesystem.
The rename is the handoff boundary. Raw shards must not be modified afterward.

Example `capture.json`:

```json
{
  "version": 1,
  "capture_block_id": "177",
  "stream_name": "sdp_vdif",
  "status": "closed",
  "shards": [
    {"name": "177_sdp_vdif.00000000", "size_bytes": 4}
  ]
}
```

`closed` means the stop was acknowledged and the file inventory was captured.
It does not certify VDIF framing, packet completeness, scientific validity, or
power-loss durability. An empty control-plane-only test cannot publish a closed
capture. A failed stop or failed closure leaves `raw.writing` for investigation.
A lost proxy process does not automatically adopt an unfinished capture.

## Postprocessor ownership

`vlbimeta <data_dir> <cbid> <stream> ...` accepts only `raw` with version-1
`capture.json`, matching identity and `closed` status. It rejects `raw.writing`
(even if it contains a manifest), simultaneous raw and raw.writing directories,
missing/duplicate/extra shards, symlinked shards, and changed file sizes. Inventory
checks are not checksums or VDIF validation.

The raw input is retained. Current pass-through and ANTAB modes hard-link its
shards into `.vdif.writing`, avoiding another full recording's disk allocation.
Source and output must be on the same filesystem. Both names refer to immutable
payload bytes: future science-only rewriting must create new files rather than
truncate or overwrite a hard link. Removing one link does not remove the other.
Raw retention/cleanup policy remains separate operational work.

Each output receives its metadata before publication. `vlbimeta` renames the
VDIF directory first, then the companion metadata directory. The companion
contains the copied capture inventory and raw/final paths in provenance.
`vdif_selection=full_capture` explicitly describes the current output: generating
an ANTAB or a scan manifest does not yet imply science-only VDIF filtering.

The two directory renames are not one atomic transaction. A failure can leave
published VDIF alongside unfinished companion metadata. Existing final or
`.writing` outputs currently cause an explicit error; they are never silently
accepted as a successful run, overwritten, resumed, or deleted. Full retry,
recovery, and pass-through-to-ANTAB upgrade semantics are subsequent work.
Disabled mode exits without requiring inputs or creating output.

## Rollout and remaining validation

Update the controller stream-name export and both images together. Old captures
require a separately reviewed migration/recovery procedure; merely renaming an
old directory does not establish that capture stopped successfully.

The controller still supplies the common data volume and pins postprocessing to
the recorder host. This contract does not change placement. Real jive5ab stop
responses, filesystem hard-link support, DLM discovery of the final directories,
and execution alongside subsequent captures still need lab validation. Payload
validity and ANTAB/UVFLG/log/filtering correctness are separate science-output
checks, not established by the handoff tests.
